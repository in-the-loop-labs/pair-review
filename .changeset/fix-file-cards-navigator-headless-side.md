Fix several small review issues. File-level AI suggestion cards from a previous analysis run or level no longer linger when the new results have no file-level findings, reloading user comments leaves the current AI cards in place, and the card of a deleted or dismissed last file-level comment is removed. Starting a new analysis now clears the previous run's file-level AI cards and the suggestion navigator list along with the inline suggestions, in Local mode as well as PR mode. When suggestions are reloaded several times in quick succession, the latest list is the one shown. The suggestion navigator keeps its selection when suggestions refresh (for example after adopting or dismissing one), and shows an error when a finding cannot be shown in the diff instead of doing nothing, but not while suggestions are being reloaded. Headless `--ai-draft` / `--ai-review` submissions now map findings the same way as submitting from the web UI: findings on deleted lines go to the LEFT side of the diff instead of always RIGHT, multi-line findings are posted as ranges, file-level findings are posted as file comments instead of being dropped, and a finding on a line outside the diff hunks is posted as a file comment with a "(Ref Line N)" prefix instead of failing the submission. Headless submissions to a GitHub-compatible alternate host now send the PR head commit with each inline comment, as the web UI does, so the host no longer rejects them with a "commit_id missing" error. A multi-line comment whose ends fall in different diff hunks, or whose lines are given in reverse order, no longer makes GitHub reject the whole review: a reversed range is put in order, and a range that cannot be one thread is posted on its first line, or as a file comment with a "(Ref Lines N-M)" prefix when that line is outside the diff. Multi-line comments on deleted lines now start on the LEFT side instead of GitHub's default RIGHT.
