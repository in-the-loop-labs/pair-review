Manage councils from the command line with the new `pair-review council <command>` subcommand: `list`, `show`, `export`, `new`, `edit`, `duplicate`, `rename`, and `delete`. `new` and `edit` open a council document in `$VISUAL`/`$EDITOR`/`vi` — multi-word values such as `code --wait` work, and quitting the editor with a non-zero status or a signal aborts without writing — and re-open the document on a validation error; `new` seeds its starter document from your default provider and model rather than assuming Claude. Edits are always staged: the editor works on a copy, so aborting — with `q`, a failed editor, or a closed stdin — leaves the original untouched, including when repairing a council file. `show` and `export` print the document on a clean stdout, so `pair-review council show <handle> > my.council.json` produces a valid council document (rename one copy before installing it as a council file, or both answer to the same handle). File-based councils can be listed, shown, exported, duplicated, and validated, but `rename` and `delete` refuse them and point at the file; a council file that fails to load is not listed at all, yet `pair-review council edit <filename-stem>` still opens it so the error can be fixed. Names are checked against the same space `--council` resolves in, so a new council cannot shadow an existing one's handle, and a name accidentally left unquoted (`council delete My Dream Team`) is rejected instead of resolving to something else. `--list-councils` still works and is now an alias for `pair-review council list`.
